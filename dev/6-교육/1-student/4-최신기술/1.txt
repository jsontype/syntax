[AI 기술 트렌드 총정리]
- 기준 시점: 2026년 7월.
- 읽는 법: 1번(큰 그림)만 읽어도 "판이 어떻게 바뀌었는지" 감이 옵니다.
        바쁘면 1 → 4(코딩툴) → 10(주의점) → 11(로드맵)만 봐도 됩니다.


==========================================================
0. 세 줄 요약
==========================================================

  - 이제 코드의 상당량은 사람이 직접 타이핑하지 않고 AI가 씁니다. 개발자의
    일은 "타이핑"에서 "명세 · 검증 · 아키텍처 · 리뷰"로 이동했습니다.
  - "AI에게 물어보는 챗봇" 시대는 끝났고, AI가 직접 파일을 읽고 고치고
    터미널을 돌리는 "에이전트(Agent)" 시대입니다. 핵심 표준어는 MCP.
  - 도구는 계속 바뀌지만 원리는 그대로입니다. 도구 이름 외우기보다
    "무엇을 AI에 맡기고 무엇을 내가 검증할지" 감각을 기르는 게 중요합니다.


==========================================================
1. 큰 그림 — 개발판이 어떻게 바뀌었나
==========================================================

1. 예전의 개발
  - 검색(스택오버플로우) → 복붙 → 수정 → 실행 → 디버깅의 반복.
  - IDE 자동완성은 "단어 단위"가 한계.
  - AI는 "번역기 / 챗봇" 정도의 보조 역할.

1. 지금의 개발
  - AI가 "함수 단위 → 파일 단위 → 여러 파일에 걸친 기능 단위"로 코드를 작성.
  - 개발자는 "무엇을, 왜 만들지"를 명세하고, AI 결과물을 "검증·수정·통합".
  - "바이브 코딩(vibe coding)"이라는 말이 생김: 세부 문법을 직접 치기보다 AI에게 의도를 말로 지시해서 앱을 만드는 방식.
    (같은 교육폴더의 3-바이브코딩 참고)

1. 역할 이동 (제일 중요한 변화)
  - 값어치가 올라간 능력: 문제 정의, 아키텍처 설계, 코드 리뷰/검증, 보안 감각, "AI가 틀린 걸 알아채는 눈".
  - 값어치가 내려간 능력: 문법 암기, 보일러플레이트 타이핑, 단순 CRUD 반복.
  - 즉, 주니어가 하던 "손"의 일이 줄고, 시니어가 하던 "판단"의 일이 늘었음.
    → 복귀하는 경력자에게 오히려 유리한 지형입니다.

1. 냉정한 현실
  - AI는 자주 그럴듯하게 틀립니다(환각, hallucination).
  - 검증 없이 그대로 배포하면 사고 납니다. "빠르게 초안, 사람이 검증"이 원칙.
  - "AI가 다 해준다"도 "AI는 장난감이다"도 둘 다 틀림. 둘 다 위험합니다.


==========================================================
2. LLM 기초 개념 (오래 쉬었으면 여기부터)
==========================================================

  용어만 알면 나머지는 다 따라옵니다.

1. LLM (Large Language Model, 대규모 언어모델)
  - 다음에 올 "토큰"을 확률로 예측하는 모델. GPT, Claude, Gemini가 다 이것.
  - "이해"한다기보다 "엄청 잘 예측"한다고 보는 게 실무에 안전.

1. 토큰(token)
  - 텍스트를 쪼갠 최소 단위(대략 단어의 일부). 요금·길이 제한이 다 토큰 기준.
  - 한국어는 영어보다 토큰을 더 많이 먹는 경향(비용/길이에 영향).

1. 컨텍스트 윈도우(context window)
  - 모델이 "한 번에 기억"할 수 있는 입력+출력 총량(토큰 수).
  - 예전엔 4K~8K로 답답했는데, 지금은 1M(백만) 토큰짜리도 흔함.
    → 코드베이스 통째로, 문서 수백 장을 한 번에 넣고 물어볼 수 있음.
  - 단, 길다고 다 잘 쓰는 건 아님. 핵심만 넣는 게 여전히 유리(비용·정확도).

1. 프롬프트(prompt) / 시스템 프롬프트(system prompt)
  - 프롬프트 = 모델에게 주는 지시/질문.
  - 시스템 프롬프트 = "너는 이런 역할이야"라고 대화 전체에 까는 밑바탕 지시.

1. 환각(hallucination)
  - 없는 API, 없는 라이브러리, 틀린 사실을 자신 있게 지어냄.
  - 그래서 "출처 제시 / 실행해서 검증 / 테스트"가 필수.

1. 멀티모달(multimodal)
  - 텍스트만이 아니라 이미지·PDF·음성·화면 스크린샷까지 입력으로 받음.
  - 스크린샷 주고 "이 UI 코드로 만들어줘", 에러 화면 캡처 주고 "왜 나?" 가능.

1. 추론 모델 / 확장 사고(reasoning, extended/adaptive thinking)
  - 답하기 전에 "속으로 단계적으로 생각"하는 모드. 수학·코딩·복잡한 로직에 강함.
  - 요즘은 모델이 알아서 "얼마나 생각할지" 조절하는 적응형(adaptive)이 표준.
  - "effort(노력 수준: low/medium/high 등)"로 깊이·비용을 조절.

1. 파라미터 감각
  - temperature(무작위성): 낮으면 일관, 높으면 창의적 — 단 최신 상위 모델들은
    이 값을 아예 안 받는 방향으로 감(프롬프트로 제어).
  - max_tokens: 출력 최대 길이. 너무 낮게 잡으면 답이 중간에 잘림.

3. 2026년 주요 AI 모델 지형도
==========================================================

  * 모델은 몇 달마다 갱신됩니다. "이름"보다 "어느 회사의 어느 급"인지 감만.
  * 가격은 100만 토큰당 입력/출력 기준(USD). 코딩 작업은 대개 상위 모델 추천.

1. Anthropic — Claude (코딩·에이전트·긴 컨텍스트에 특히 강함)
  - Claude Opus 4.8 : 최상위 범용/코딩/에이전트. 컨텍스트 1M. ($5 / $25)
  - Claude Sonnet 5 : 속도·가격·성능 밸런스. 대량 프로덕션용. ($3 / $15)
  - Claude Haiku 4.5 : 가장 빠르고 저렴. 단순·대량 작업용. ($1 / $5)
  - Claude Fable 5 : 가장 어려운 장기 추론/에이전트용 최상급. ($10 / $50)
  - Claude Code(터미널/IDE에서 도는 에이전트형 코딩 툴)의 기반 모델.

1. OpenAI — GPT / o-시리즈
  - 가장 유명, 생태계·플러그인·이미지생성 등 넓음. ChatGPT의 그 회사.
  - "추론 특화 모델"과 "범용 모델" 라인이 나뉘어 있음.

1. Google — Gemini
  - 검색·워크스페이스(문서/메일) 연동, 초장문 컨텍스트, 멀티모달 강점.

1. 오픈소스 / 오픈웨이트 (내 서버·내 PC에서 돌림)
  - Llama(Meta), DeepSeek, Qwen(알리바바), Mistral 등.
  - 장점: 무료·데이터 외부 유출 없음(프라이버시). 단점: 인프라·품질 관리 필요.
  - 로컬 실행 도구: Ollama, LM Studio (개인 PC에서 모델 띄우기 쉬움).

1. 한국어
  - 한국어 품질은 위 글로벌 상위 모델들이 이미 매우 좋음.
  - 국산 모델(예: 네이버 계열 등)도 있으나, 코딩/추론은 글로벌 상위권이 우세.

1. 모델 고르는 실무 기준
  - 어려운 코딩/설계 → 각 사의 최상위 모델(예: Claude Opus 4.8).
  - 대량·비용 민감 → 중급(예: Sonnet 5).
  - 단순 분류/요약 대량 → 소형·저렴(예: Haiku 4.5).
  - 민감 데이터·오프라인 → 오픈소스 로컬.

4. AI 코딩 도구 (실무에서 제일 중요)
==========================================================

  형태별로 세 부류가 있습니다. 하나만 골라 손에 익히면 됩니다.

1. IDE 통합형 (기존 에디터 안에서)
  - GitHub Copilot : 원조. VSCode/JetBrains 자동완성 + 채팅.
  - Cursor : VSCode 포크. "코드베이스 전체를 이해하는" AI 에디터로 인기 급상승.
  - Windsurf 등 유사 제품 다수.

1. 에이전트형 CLI / 터미널 (스스로 파일 읽고 고치고 실행)
  - Claude Code : 터미널에서 도는 에이전트. 파일 수정·명령 실행·테스트·커밋까지.
  - Codex CLI, Aider, Cline 등.
  - 특징: "이 버그 고쳐줘" 하면 알아서 관련 파일 찾고 → 수정 → 실행 → 확인.

1. 웹/노코드형 (앱을 통째로 생성)
  - v0, bolt, lovable, Replit Agent 등.
  - 자연어로 "이런 앱 만들어줘" → 배포 가능한 초안까지. 비개발자·프로토타입용.

1. 실무 팁
  - 처음엔 "IDE 통합형(Cursor/Copilot)"으로 자동완성부터 익히고,
    익숙해지면 "에이전트형(Claude Code 등)"으로 넘어가는 흐름을 추천.
  - AI에게 일 시키는 요령:
    · 맥락을 충분히 줘라(관련 파일, 목표, 제약).
    · 에러는 그대로 통째로 던지지 말고 "무엇을 시도했고 뭐가 났는지" 함께.
    · 큰 작업은 한 번에 시키지 말고 잘게 쪼개서 단계별로.
    · 결과는 반드시 읽고 검증. AI 코드 그대로 커밋 금지.

5. 에이전트 & 핵심 개념 (신규 표준어 모음)
==========================================================

  복귀하면 회의에서 이 단어들이 쏟아집니다. 뜻만 알아두면 됩니다.

1. 에이전트(Agent)
  - "질문에 답만 하는 챗봇"이 아니라, 목표를 주면 스스로 도구를 써서
    여러 단계를 수행하는 AI. (검색 → 파일 수정 → 실행 → 재시도 …)

1. Tool use / Function calling (도구 호출)
  - LLM이 "내가 직접 함수/API를 호출하겠다"고 정해서 외부 기능을 부르는 것.
  - 예: 날씨 API 호출, DB 조회, 이메일 발송을 AI가 알아서 트리거.

1. MCP (Model Context Protocol) — ★꼭 기억★
  - AI 에이전트가 "외부 도구·데이터(깃허브, 슬랙, DB, 파일시스템 등)"에
    연결되는 표준 규격. USB-C 같은 "AI용 표준 단자"라고 보면 됨.
  - 요즘 나오는 툴들은 대부분 "MCP 서버"를 붙여서 기능을 확장함.
  - 면접·회의에서 자주 나오는 최신 키워드 1순위.

1. RAG (Retrieval-Augmented Generation, 검색증강생성)
  - 모델이 모르는 "우리 회사 내부 문서"를 답에 반영하는 기법.
  - 흐름: 문서를 잘게 쪼개 → 벡터로 변환(임베딩) → 벡터DB 저장 →
    질문과 유사한 조각을 찾아 프롬프트에 끼워넣어 → 그 근거로 답하게.

1. 임베딩(embedding) / 벡터DB
  - 임베딩 = 텍스트를 "의미 좌표(숫자 벡터)"로 바꾼 것.
  - 벡터DB = 그 벡터들을 저장하고 "의미가 비슷한 것"을 빠르게 찾는 DB.
    (예: Pinecone, Weaviate, pgvector, Qdrant 등)

1. 구조화 출력(structured output)
  - AI가 자유 문장이 아니라 "정해진 JSON 스키마"로만 답하게 강제하는 기능.
  - 프로그램이 파싱하기 쉬워서 실무에서 매우 중요.

1. 프롬프트 캐싱(prompt caching)
  - 매번 똑같이 들어가는 긴 앞부분(시스템 프롬프트 등)을 캐시해서
    비용/속도를 크게 절약. 실서비스 비용 최적화 핵심.

1. 멀티에이전트 / 서브에이전트
  - 큰 일을 여러 AI가 나눠서(병렬로) 처리하고 결과를 합치는 구조.

6. AI 앱을 직접 만든다면 (API·스택)
==========================================================

1. API 연동
  - 각 사 공식 SDK로 호출(Python: anthropic / openai, JS: 각 사 SDK).
  - 스트리밍(토큰 실시간 출력), tool use, 구조화 출력, 캐싱 등이 기본 제공.

1. 자주 쓰는 프레임워크
  - LangChain / LlamaIndex : RAG·에이전트 파이프라인 조립 (강력하지만 무거움).
  - Vercel AI SDK : 웹 프론트에서 스트리밍 채팅 붙일 때 편함.
  - 요즘 흐름: "프레임워크 없이 SDK로 직접" + "필요할 때만 프레임워크".

1. 운영에서 챙길 것
  - 평가(eval) : 프롬프트/모델 바꿀 때 품질이 유지되는지 자동 채점.
  - 관측(observability) : 요청·비용·지연·실패를 로깅/모니터링 (예: Langfuse).
  - 가드레일·안전 : 프롬프트 인젝션, 민감정보 유출, 부적절 출력 방어.
  - 비용 관리 : 토큰 = 돈. 캐싱·모델 등급 선택·출력 길이 제한으로 통제.

1. 관리형 에이전트(Managed Agents)
  - 에이전트 루프와 실행 샌드박스(컨테이너)를 클라우드가 대신 돌려주는 서비스.
  - 직접 인프라 안 만들고 "상태 유지되는 에이전트"를 서버에 띄우고 싶을 때.


==========================================================
7. 프롬프트 & 컨텍스트 엔지니어링 (실무 기술)
==========================================================

1. 좋은 프롬프트의 원칙
  - 역할·목표·제약·출력형식을 명확히. ("~하는 시니어 리뷰어로서, 500자 이내로")
  - 맥락(관련 코드/데이터)을 충분히 제공. 추측하게 두지 말 것.
  - 예시 1~2개(few-shot) 주면 형식 준수도가 확 올라감.
  - 복잡하면 "단계별로 생각해" 대신, 추론 모델을 쓰거나 작업을 쪼개기.

1. "질문을 시키는" 역질문 기법 (매우 유용)
  - "X를 하기 위해 필요한 정보를 나에게 먼저 질문해. 다 모이면 그때 코드를 써."
  - 그럼 AI가 빠진 정보를 되물어봄 → 답만 채우면 정확한 결과가 나옴.

1. 컨텍스트 엔지니어링
  - "무엇을 프롬프트에 넣을지" 설계하는 것. 요즘은 프롬프트 문구보다
    "어떤 맥락을 어떤 순서로 넣느냐"가 성패를 가름.
  - 긴 대화가 컨텍스트를 넘기면 요약(compaction)·정리(context editing)로 관리.


==========================================================
8. AI 말고도 바뀐 것들 (일반 개발 트렌드)
==========================================================

  AI만 바뀐 게 아닙니다. 쉬는 동안 이 정도가 움직였습니다.

1. 프론트엔드
  - TypeScript가 사실상 표준(순수 JS는 소규모/학습용).
  - React 여전히 주류. 단 서버 컴포넌트(RSC)·Next.js App Router로 패러다임 변화.
  - 경량 대안 인기: Svelte, SolidJS, Astro(콘텐츠·SEO 강함).
  - 빌드 도구: webpack 지고 Vite가 표준. 번들러 esbuild/swc(초고속).

1. 런타임 / 언어
  - Node 외에 Bun(초고속 올인원), Deno 등장.
  - 백엔드에서 Go, Rust 채택 증가(성능·안정성). Python은 AI/데이터로 더 강해짐.
  - WebAssembly(Wasm) 활용 확대.

1. 인프라 / 배포
  - 엣지 컴퓨팅·서버리스 대중화 (Cloudflare Workers, Vercel 등).
  - 컨테이너(Docker)·쿠버네티스는 여전히 표준 교양.
  - BaaS(Supabase, Firebase)로 DB+인증+API를 빠르게. (개인/스타트업)
  - 프론트 배포는 git push → 자동배포가 기본값이 됨.

1. 데이터베이스
  - PostgreSQL이 여전히 강세(+ 벡터 확장 pgvector로 AI까지 커버).
  - 서버리스 DB(Neon, Turso 등), ORM은 Prisma/Drizzle.

  (더 상세한 33개 기술 선택지 비교표는
   같은 교육폴더의 3-바이브코딩(초보자용)/앱만들때선택지.md 참고)

9. 개발 워크플로우의 변화
==========================================================

  - Git은 그대로. 다만 커밋 메시지·PR 설명·코드리뷰를 AI가 도와줌.
  - AI 코드리뷰가 CI에 들어옴(자동으로 버그·취약점 지적).
  - "이슈 → AI 에이전트가 초안 PR 생성 → 사람이 리뷰/머지" 흐름 확산.
  - 테스트의 중요도 상승: AI가 짠 코드를 "테스트로 검증"하는 게 안전장치.
  - 문서·회의록·릴리즈노트 자동 생성이 일상.

10. 마인드셋 & 주의점 (반드시 읽기)
==========================================================

1. 검증이 곧 실력
  - AI 결과를 "읽고 이해하고 판단"하는 사람이 살아남음. 그대로 붙이는 사람 위험.
  - 이해 못 하는 코드는 커밋하지 말 것.

1. 보안·프라이버시
  - 사내 소스/고객정보/키를 함부로 외부 AI에 붙여넣지 말 것(회사 정책 확인).
  - 프롬프트 인젝션: 외부 입력이 AI 지시를 덮어쓰는 공격 → 신뢰경계 설계.
  - API 키·비밀번호는 코드/프롬프트에 절대 넣지 말 것(환경변수·시크릿 매니저).

1. 과신·자동화 함정
  - AI가 "그럴듯하게 틀린" 걸 걸러낼 사람이 결국 필요.
  - 되돌리기 어려운 작업(삭제·배포·결제·메일발송)은 사람이 최종 확인.

1. 비용 감각
  - 토큰은 돈. 무한정 큰 모델·긴 프롬프트로 돌리면 요금 폭탄.
  - 모델 등급 선택 + 캐싱 + 출력 길이 제한으로 통제.

1. 학습 태도
  - 도구 이름은 6개월이면 바뀜. 원리(LLM·에이전트·RAG·검증)를 잡으면 안 흔들림.
  - "AI를 안 쓰는 개발자"가 아니라 "AI를 잘 부리는 개발자"가 표준이 됨.

11. 복귀 30 / 60 / 90일 로드맵
==========================================================

1. 0~30일 : 감 되찾기 + AI 손에 익히기
  - AI 코딩 툴 하나 정해 매일 쓰기(추천: Cursor 또는 Claude Code).
  - LLM 기초 개념(2번) 확실히. 챗봇에 "이 개념 예제로 설명해" 반복.
  - 작은 개인 프로젝트 하나를 바이브 코딩으로 처음부터 끝까지 배포까지.

1. 30~60일 : 실무 근육
  - 현업 언어/프레임워크 최신 버전 문법 갱신(AI에게 "예전 X → 지금 Y 차이" 질문).
  - AI 코드를 "리뷰·수정·테스트"하는 훈련. 그대로 안 믿는 습관.
  - RAG·tool use·구조화 출력·MCP 개념을 손으로 한 번씩 만들어보기.

1. 60~90일 : 설계·운영
  - AI 기능을 실제 서비스에 붙여보기(API 연동 + 스트리밍 + 캐싱 + 평가).
  - 비용·보안·관측까지 고려한 "돌아가는 것"을 만들어 포트폴리오화.
  - 팀 워크플로우(AI 리뷰, 에이전트 PR)에 자연스럽게 합류.

12. 한 줄 용어 사전
==========================================================

  LLM        : 다음 토큰을 예측하는 대규모 언어모델(모든 AI의 뿌리).
  토큰       : 텍스트 최소 단위. 요금·길이의 기준.
  컨텍스트   : 한 번에 기억하는 입력+출력 총량.
  프롬프트   : AI에게 주는 지시/질문.
  환각       : AI가 그럴듯하게 지어내는 오류.
  멀티모달   : 텍스트+이미지+음성+화면을 함께 다룸.
  추론모델   : 답 전에 단계적으로 "생각"하는 모델.
  에이전트   : 스스로 도구를 써서 여러 단계를 수행하는 AI.
  Tool use   : AI가 외부 함수/API를 직접 호출.
  MCP        : AI-도구 연결 표준 규격(USB-C 같은 것).
  RAG        : 내부 문서를 검색해 근거로 답하게 하는 기법.
  임베딩     : 텍스트를 의미 벡터(숫자)로 변환.
  벡터DB     : 의미가 비슷한 것을 찾는 DB.
  바이브코딩 : 문법 대신 의도를 말로 지시해 앱을 만드는 방식.
  구조화출력 : AI가 정해진 JSON 형식으로만 답하게 강제.
  프롬프트캐싱: 반복되는 앞부분을 캐시해 비용/속도 절약.
  프롬프트인젝션: 외부 입력이 AI 지시를 탈취하는 공격.
