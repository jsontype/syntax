1. テスト環境 (대시보드 우상단 토글)
  본番과 같은 상품 · Payment Link 를 테스트 환경에도 만들고 테스트 카드로 흐름 확인
    4242 4242 4242 4242  성공
    4000 0000 0000 3220  3D セキュア 인증 화면
    4000 0000 0000 9995  잔액 부족
  웹훅도 테스트용 destination 을 따로(시크릿이 다르다). Send test event 로 서명 · KV 연결 확인 → 200 (가짜 이벤트라 발급은 되지 않음: skipped unpaid / not-utils-product)

1. 본番 링크를 앱에
  buy.stripe.com/… (test_ 없는 것) 을 biz.js 의 checkout 에 → 로컬에서 버튼이 「購入する」 로 바뀌는지 → 커밋 · 푸시 (푸시 = 본番)

1. 본인 카드로 실결제 1건 (買い切り)
  확인: 카드 명세서 표기 BROODEV UTILS · 영수증 메일에 税込 / 税額 / T번호 · 인보이스 PDF · 라이선스 메일 도착(키 + 활성화 링크)
  → 메일 링크로 활성화 → pptx 다운로드 해제 → 대시보드에서 返金 → 환불 메일 · 웹훅이 라이선스 무효화 → 요금 페이지 새로고침(재검증) 시 잠금 복귀
  수수료는 환불해도 돌아오지 않는다 (¥5,000 × 3.6% = ¥180 — 1회 테스트 비용)

1. 年額 도 1건
  포털에서 「期間終了時にキャンセル」 가 되는지 · 갱신 리마인더 설정 확인 → 환불 + 구독 취소

1. 개시
  포털 카탈로그의 앱 설명에 「프리미엄」 한 줄 · 총람 카드가 요금 페이지/앱 모달로 연결되는지 · 필요하면 OG 갱신(카카오 캐시 초기화)
  모니터링: Stripe 대시보드 「要対応」 · 웹훅 destination 의 실패 이벤트(500 이면 Stripe 가 3일 재시도) · KV 의 mail_error
